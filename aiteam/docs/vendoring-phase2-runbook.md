# Vendoring Runbook — Phase 2 (move) & Phase 3 (shims/installer)

> Companion to [ADR 0002](adr/0002-vendored-folder-layout.md). Phase 1 (the
> `repoRoot()` helper + re-anchoring of state readers) is **done and committed**
> (`efd105a`). This runbook is the exact, mechanical execution of Phases 2–3 so
> a future session can run it without re-deriving anything.
>
> Inventory captured 2026-06-30 against commit `efd105a`. If the tree drifts,
> re-run the greps in §6 before trusting the reference list.

## 0. Preconditions
- Clean working tree; full suite green (`npx vitest run` → 127 passing).
- **Branch name must NOT contain `/`.** The `.beads` per-branch hooks build
  `.beads/<branch>.yaml`; a `chore/x` name → `.beads/chore/x.yaml` whose parent
  dir does not exist → `cp` fails (observed). Use e.g. `vendoring-phase2`.
- Everything is committed, so `git mv` works uniformly (tracked files only).

## 1. Target: what STAYS at root vs MOVES
**Stays at host root** (state/interface + tool conventions that must be read
from root): `SPEC.md`, `.beads/`, `.claude/settings.json`,
`.claude/tier-rules.json`, `.mcp.json`, `.gitignore`, `.gitattributes`,
`.github/` (GitHub only runs workflows from the root), and thin
`CLAUDE.md`/`AGENTS.md`/`GEMINI.md` shims (Phase 3).

**Moves into `aiteam/`** (everything else). Delete `.claude/agent-memory/`
(committed personal artifacts) during the move.

## 3. Reference rewrites (file-by-file, exact)

### 3a. Build/runtime config (now under `aiteam/`)
- `aiteam/tsconfig.json` — `include` globs `src/**/*`, `scripts/**/*` are already
  relative to the tsconfig dir → **no change** once the file sits in `aiteam/`.
  Confirm `rootDir`/`outDir` still make sense (rootDir `.` = `aiteam/`).
- `aiteam/vitest.config.ts` — `include: ["src/**/*.test.ts", "evals/**/*.test.ts", ".mcp/**/*.test.ts"]`
  → change `.mcp/**` to `mcp/**` (the dot is gone). Coverage `include: ["src/**/*.ts"]` ok.
- `aiteam/package.json` — script paths are relative (`scripts/*.ts`) → no change.
  Keep only framework deps here; the host package.json is untouched. Recommend an
  npm **workspace** in the host root so `aiteam` deps resolve.

### 3b. Path resolution still on `process.cwd()` (decide per call)
Phase 1 already routed the 5 state readers through `repoRoot()`. Remaining
`process.cwd()` sites (from §6 grep) and the verdict:
- `aiteam/scripts/validate-beads.ts:16` → reads `.beads/active.yaml` (root state).
  **Change** default to `path.resolve(repoRoot(), ".beads/active.yaml")` so
  `npm --prefix aiteam run validate:beads` works. (When the git hook calls it
  from root it already passes the path, but the npm script must not depend on cwd.)
- `aiteam/scripts/metrics.ts:10` → `.beads/session-log.ndjson` (root state).
  **Change** to `repoRoot()`.
- `aiteam/scripts/bootstrap-beads.ts:159`, `generate-spec.ts:180` → `argv[2] ?? cwd`.
  These scaffold INTO a target project. **Keep cwd** (operate-on-this-dir).
  *(Superseded: with `npm --prefix aiteam run`, cwd is `aiteam/`, so the default
  wrote into the vendored framework. Both now default to `defaultTargetDir()`
  in `aiteam/src/repo-root.ts` — the repo root — and still take an explicit
  directory.)*
- `aiteam/src/eval-suite.ts:129/157/158`, `evals/run.test.ts:29` → framework-internal
  eval/prompt paths, run with cwd=`aiteam/`. **Keep cwd.**
- `aiteam/hooks/tier-guard.mjs:17` `const REPO = process.cwd()` → the PreToolUse
  hook runs with cwd = repo root and reads root-resident `SPEC.md` /
  `.claude/tier-rules.json`. **Keep cwd.** (Only its import path changes — §4.)

### 3c. Config that stays at root but points into `aiteam/`
- `.mcp.json` — `args: ["tsx", ".mcp/server.ts"]` → `["tsx", "aiteam/mcp/server.ts"]`.
- `.claude/settings.json` — hook `command: "node .claude/hooks/tier-guard.mjs"`
  → `"node aiteam/hooks/tier-guard.mjs"`. (deny rules are tool-pattern based → unchanged.)
- `.gitattributes` — maps `.beads/*.yaml` (stays root) → **no change**; only the
  comment pointing at `scripts/beads-merge.ts` is now `aiteam/scripts/beads-merge.ts`.
  *(Historical: since rb-ai-team#37 that mapping is gone — the sync tells every
  consumer to drop the `merge=beads-yaml` block, legacy mode included; see
  [`consuming-as-upstream.md`](consuming-as-upstream.md).)*
- `.github/workflows/eval.yml` — MUST stay at `.github/workflows/`. Add
  `defaults: { run: { working-directory: aiteam } }` so `npm ci`/`npm run *`
  resolve `aiteam/package.json`; prefix the `paths:` filters with `aiteam/`
  (`aiteam/prompts/**`, `aiteam/evals/**`, `aiteam/src/circuit-breaker.ts`,
  `aiteam/src/eval-suite.ts`, `aiteam/mcp/tools/**`, `aiteam/package*.json`).
  `actions/setup-node` cache: set `cache-dependency-path: aiteam/package-lock.json`.
- **The host app's own CI does not come with the vendoring.** `aiteam/` brings
  the framework's checks, never the app's. A workflow with a top-level
  `defaults.run.working-directory: aiteam` — the `eval.yml` above, or a copy of
  the framework's `ci.yml` — runs every step inside `aiteam/`, so the app's
  `npm run test` and the framework's become the same string in the YAML and the
  app's suite never runs on a PR, with CI green (rb-ai-team#31). The host needs
  a PR job of its own at the app's root — start from
  `aiteam/templates/ci.yml.example`, job `app` — and the commands it runs
  declared in the `ci:` block of `SPEC.md` (`aiteam/AGENTS.md` §CI/CD Mandate,
  item 1), which `aiteam/src/ci-contract.test.ts` and the doctor check.

### 3d. The git hooks (now `aiteam/githooks/` + `aiteam/hooks/`)

- Script refs `scripts/validate-beads.ts`, `scripts/beads-merge.ts`,
  `scripts/scan-secrets.ts` → `aiteam/scripts/...`.
- `.beads/` paths stay (root); hooks run with cwd = repo root.
- The merge-driver registration `npx tsx scripts/beads-merge.ts` →
  `npx tsx aiteam/scripts/beads-merge.ts`. *(Historical: the hooks no longer

### 3e. The Bead Board server

resolves to `aiteam/`, but it reads root-resident `.beads/active.yaml` and

`subprocess.run(["git","rev-parse","--show-toplevel"])` (robust) or `parent`×4.

## 7. Phase 3 — root shims + installer (`aiteam/install.mjs`)
- Root `CLAUDE.md`/`AGENTS.md`/`GEMINI.md` shims: a single `@aiteam/CLAUDE.md`
  (etc.) import line, so a host's own files merge by adding one line.
- Root `README.md` shim: short pointer to `aiteam/README.md`.
- `aiteam/install.mjs` (idempotent):
  1. **Git hooks:** `core.hooksPath` is single-valued → CHAIN, do not clobber.
     Detect the host's existing hooks; write shims that `exec aiteam/githooks/<hook> "$@"`.
  2. **Config merge:** merge the framework's `.claude/settings.json` (deny +
     PreToolUse) and `.mcp.json` (server entry) into the host's; inject the
     `@aiteam/...` import lines into root CLAUDE.md/AGENTS.md.
- Update `aiteam/docs/consuming-as-upstream.md` + `legacy-onboarding.md` to the
  vendored layout (host adds `aiteam/` as a subtree/submodule or copies it; runs
  `node aiteam/install.mjs`).

### 7a. Running-guarantee + non-interference (user observation 1)
The deployer must be able to confirm the framework is *active* in the host
WITHOUT it interfering with the host's own tooling.
- **`aiteam doctor`** (`node aiteam/scripts/doctor.mjs`, also `npm --prefix aiteam
  run doctor`): a read-only check that prints PASS/FAIL for each wiring point —
  `.claude/settings.json` has the PreToolUse tier-guard, `.mcp.json` references
  `aiteam/mcp/server.ts`, the git hooks are chained (not clobbered), `repoRoot()`
  resolves, `tier-rules.json` loads, `validate:beads` passes, and a sample
  Tier-3 command is denied by the hook. No mutations.
- **Non-interference invariants** the installer MUST uphold (assert in `doctor`):
  1. Never overwrite a host file — only merge into `.claude/settings.json` /
     `.mcp.json` and APPEND one `@aiteam/…` line to root `CLAUDE.md`/`AGENTS.md`.
  2. Never replace `core.hooksPath` — chain the host's existing hooks; if the
     host had none, set it, else install router shims that `exec` both.
  3. All framework deps stay in `aiteam/node_modules` (own `package.json` /
     workspace) — the host lockfile is untouched.
  4. Tier-3 gating defaults to deny; the framework never relaxes a host setting.
- Tracked as bead `infra-framework-doctor`.
